당신은 프로덕트 디자이너이자 기독교 영성 형성 전문가입니다.

## 과제: DailyQT의 "매일 순환 루프" 설계

### 배경
개인화된 QT 앱에서 사용자가 온보딩을 완료하고 첫 30일 플랜을 시작합니다.
현재 시스템은 "플랜 완료 → 다음 주제 추천"까지만 구현되어 있습니다.

하지만 실제 서비스에서는 이런 시나리오들이 발생합니다:

1. 30일 플랜 완료 → 다음 주제 시작 → 또 완료 → ...계속 반복
2. 선택한 주제 전부 소진 → 그 다음은?
3. 6개월 사용 → 입문→초급으로 성장 → 같은 주제를 더 깊은 단계로?
4. 1년 사용 → 처음 했던 "불안" 주제를 다시? 새로운 구절로?
5. 매일매일 들어오게 하는 동기는? 안 들어오면?

### 설계해야 할 것

#### 1. 일일 루프 (Daily Loop)
사용자가 매일 앱에 들어왔을 때의 경험:
- 진행 중인 플랜이 있을 때: 오늘의 QT 표시
- 플랜이 끝난 직후: 다음 플랜 전환 (자동? 수동?)
- 모든 플랜 소진: 어떤 화면?
- 아무것도 안 하고 넘긴 날: 다음 날 어떻게?

#### 2. 플랜 전환 로직 (Plan Transition)
A 플랜 완료 → B 플랜 시작 사이에:
- 즉시 자동 전환? 하루 쉬는 날?
- 완료 축하 + 회고(지난 30일 돌아보기)?
- 다음 주제는 온보딩 때 선택한 큐에서? 시스템 추천?
- 같은 카테고리 연속 방지는 플랜 전환에도 적용?

#### 3. 주제 소진 후 (Topic Exhaustion)
온보딩에서 3개 주제를 선택했고 다 완료했을 때:
- "새로운 주제를 탐색하세요" → 간이 온보딩(상황 카드만)?
- 시스템이 사용자 히스토리 기반으로 자동 추천?
- "지금 마음 상태는 어떠세요?" → 상황 체크인(미니 온보딩)?
- 성경 통독 모드로 전환?

#### 4. 성숙도 진화 (Maturity Progression)
- 입문자가 3개 주제 완료 → 초급으로 올릴 것을 제안?
- 같은 "불안" 주제를 초급 SOAP으로 다시?
- 구절은 같되 가이드만 다르게? 구절도 새로?
- 자동 상승? 사용자 확인?

#### 5. 장기 참여 설계 (Long-term Engagement)
1개월 / 3개월 / 6개월 / 1년 사용자의 경험 차이:
- 마일스톤 (30일/100일/365일 축하)
- 성장 리포트 (지금까지 묵상한 주제/구절 통계)
- 계절/절기 연동 (부활절에 "부활" 주제 추천)
- 커뮤니티 연동 (나눔 탭에서 같은 주제 묵상자끼리)

#### 6. 이탈 방지 & 복귀 (Retention & Re-engagement)
- 1일 미접속: 아무것도 안 함
- 3일 미접속: 앱 내 부드러운 안내
- 7일 미접속: "괜찮으세요?"
- 30일+ 미접속: 복귀 시 "어서오세요, 다시 시작할까요?"
- 이전 진행 이어가기 vs 새로 시작 선택

### 출력 형태
1. **상태 머신 다이어그램**: 사용자의 모든 상태와 전환을 정의
   (진입 → 온보딩 → 플랜진행 → 완료 → 전환 → ... → 소진 → 재탐색)
2. **각 상태에서의 UI 화면 설명** (무엇을 보여줄지)
3. **전환 트리거 조건** (어떤 이벤트가 다음 상태로 보내는지)
4. **데이터 구조 변경점** (DB 테이블이나 API 추가 필요한 것)
5. **마일스톤 테이블** (일수별 이벤트/보상)
6. **이탈 방지 메시지 10개** (일수별, 따뜻하고 비판단적)
