## 과제: 개인화 QT 시스템의 엣지 케이스 분석 및 해결책

개인화된 QT 앱에서 발생할 수 있는 모든 예외 상황을 분석하고 각각에 대한 해결책을 제시해주세요.

## 시스템 개요
- 140개 주제, 각 30일 커리큘럼
- 4단계 성숙도 (입문/초급/중급/심화)
- 복수 주제 선택 → 순차 진행
- 건너뛴 날은 이어하기(B형)

## 분석해야 할 엣지 케이스

### 1. 플랜 진행 관련
- 30일 플랜 중 15일째에 주제를 바꾸고 싶다면?
- 성숙도를 중간에 변경하면 이미 진행한 가이드는?
- 2개 플랜을 동시에 진행하고 싶다면?
- 1년 동안 안 들어왔다가 복귀하면?
- 30일 플랜을 완료하고 같은 주제를 다시 하고 싶다면?
- 모든 선택 주제를 완료했는데 새 주제를 추가하고 싶다면?

### 2. 데이터 관련
- 4단계 상세 가이드가 없는 주제(130개 중 아직 미생성)를 선택하면?
- curricula-extended에도 없는 완전히 새로운 주제를 원하면?
- 같은 성경 구절이 여러 주제에 겹치면?
- 7일 플랜과 30일 플랜이 모두 있을 때 어떤 걸 추천?

### 3. 사용자 행동 관련
- 매일 QT를 하지 않고 일주일에 2-3번만 하는 사용자
- 하루에 여러 Day를 한꺼번에 하고 싶은 사용자
- SOAP 묵상을 전혀 작성하지 않고 완료만 누르는 사용자
- 계정을 삭제했다가 다시 가입하면?

### 4. 영적 돌봄 관련
- "자살 충동", "학대/폭력 피해" 같은 위기 주제를 선택한 사용자에게 어떤 추가 안내가 필요한가?
- 우울 주제 30일 후에도 호전이 없다고 느끼는 사용자에게?
- 가벼운 주제(감사)만 계속 선택하고 깊은 주제를 회피하는 패턴이 보이면?

## 요구 사항

각 엣지 케이스에 대해:
1. 상황 설명 (한 줄)
2. 위험도 (상/중/하)
3. 해결책 (구체적인 시스템 동작)
4. UI에서 보여줄 메시지 (사용자에게)

최종적으로 "엣지 케이스 처리 규칙 테이블"을 JSON 형태로 정리해주세요.

### 1. 예시 입력/출력에 대한 논리적 추론 및 평가

> **입력:** 성숙도=초급, 주제=["불안", "감사", "부부갈등", "기도", "직장생활"]  
> **기대 출력:** ["불안", "기도", "부부갈등", "감사", "직장생활"]

**전문가 평가: 제시해주신 기대 출력은 목회 상담학과 기독교 교육학 관점에서 '완벽에 가까운 최적의 순서'입니다.** 

단순히 영적 성장의 기본 흐름(감정→관계→신앙)만 기계적으로 따르면 `[불안 → 부부갈등 → 기도]` 순서가 되어야 합니다. 하지만 "불안(감정)"과 "부부갈등(관계)"은 둘 다 감정적 에너지를 크게 소모하는 **'무거운(Heavy) 주제'**입니다. 초급자가 이를 연달아 직면하면 영적 소진(Burnout)이 올 수 있습니다. 

따라서 다음과 같은 **'영적 호흡(Spiritual Pacing)'**의 큐레이션이 가장 이상적입니다.
1. **1일차 (불안):** 내면의 고통을 공감받고 상처를 직면하는 **치유**
2. **2일차 (기도):** 현실의 어려운 문제에 맞서기 전, 하나님과 소통하며 에너지를 얻는 **영적 환기(Breathing)**
3. **3일차 (부부갈등):** 기도로 얻은 영적 힘을 바탕으로 수평적 **관계 회복** 시도
4. **4일차 (감사):** 갈등을 극복하며 내면에 긍정적 변화가 일어나는 **성품**의 열매
5. **5일차 (직장생활):** 내면과 관계가 모두 정돈된 후 세상으로 나아가는 **사명**

아래 설계된 알고리즘은 '무거운 주제 연속 방지'라는 수학적 페널티 공식을 통해 이 완벽한 흐름을 정확하게 자동 도출해냅니다.

### 2. 카테고리별 기본 우선순위 가중치 테이블 ($W_{base}$)

영적 성장 5단계 흐름을 뼈대로 하되, 성숙도(4단계)에 따라 영적 소화력이 다르므로 가중치(100점 만점)의 무게중심을 다르게 배정합니다.

| 카테고리 (분류) | 입문 | 초급 | 중급 | 심화 | 기독교 교육학적 설계 의도 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **0. 삶의 상황(위기)**| 100 | 100 | 100 | 100 | 고난/위기 상황은 성숙도 불문 최우선 처방 |
| **1. 감정/내면** | **90** | **85** | 70 | 60 | 초신자일수록 교리적 가르침보다 정서적 공감이 선행되어야 함 |
| **2. 관계** | 80 | 80 | 75 | 70 | 내면이 안정된 후 타인과의 수평적 갈등 회복으로 나아감 |
| **3. 신앙 성장** | 60 | 75 | **85** | 80 | 초~중급 단계에서 영적 기초(말씀, 기도)를 단단히 세움 |
| **4. 성품/덕목** | 50 | 65 | 80 | **85** | 신앙이 내재화되어 인격적 열매를 맺는 성화의 과정 |
| **5. 생활 (사명)** | 40 | 55 | 70 | **90** | 신앙을 세상을 향해 실천하는 단계. 심화될수록 비중 증가 |
| **6. 신학/교리** | 20 | 40 | 65 | **95** | 입문자에겐 무거우나 심화자에게는 흔들리지 않는 영적 뼈대 |

### 3. 우선순위 점수 산출 공식 및 연속 방지 규칙

알고리즘은 변하지 않는 **'초기 점수'**를 부여한 뒤, 다음 날짜 묵상을 고를 때마다 변하는 **'동적 점수'**로 순서를 결정합니다.

**A. 초기 점수 (Initial Score)**
> **$Score_{init} = W_{base} + B_{order} + B_{crisis}$**
*   **$W_{base}$**: 위 테이블의 성숙도별 카테고리 점수
*   **$B_{order}$ (선택 순서 보너스)**: 사용자가 무의식적으로 먼저 누른 주제가 가장 갈급한 고민일 확률이 높음. `(총 선택 개수 - 인덱스) * 2점` 
*   **$B_{crisis}$ (위기 보너스)**: 주제 메타데이터에 `is_crisis = True` (자살충동, 중독, 파산 등)가 있으면 **+1000점** 부여.

**B. 동적 점수 산출 (Dynamic Penalty System - 연속 방지 규칙)**
> **$Score_{dynamic} = Score_{init} - P_{category} - P_{heavy}$**

남은 주제들을 평가할 때 **'직전에 배치된 주제의 속성'**을 기준으로 페널티를 부여합니다.
1. **$P_{category}$ (동일 카테고리 연속 방지):** 직전 주제와 카테고리가 같다면 **-30점**.
2. **$P_{heavy}$ (무거운 주제 연속 방지):** 모든 140개 주제에 `is_heavy` 속성(감정/인지 소모가 큰 주제. 예: 불안, 이혼, 깊은 교리)을 둡니다. 직전 주제가 `Heavy`였는데 다음 후보도 `Heavy`라면 **묵상 분량에 따라 차등 페널티**를 줍니다.
   - 묵상 분량 **짧음(5분)**: 페널티 **-40점** (연달아 소화 불가)
   - 묵상 분량 **보통(10분)**: 페널티 **-20점**
   - 묵상 분량 **많음(20분+)**: 페널티 **-5점** (깊은 연속 묵상 감당 가능)

---

### 4. 엣지 케이스 처리 방안

1. **1개만 선택한 경우**: 계산 연산을 생략하고 즉시 해당 묵상을 제공합니다(`O(1)`). 해당 QT 완료 후 "다음 단계 추천 시스템"을 띄워 영적 확장을 유도합니다.
2. **10개를 선택한 경우**: 알고리즘이 완벽하게 작동하여 `[감정(Heavy) → 신앙(Light) → 관계(Heavy) → 성품(Light)...]` 식으로 10일간 지루함 없이 리듬감 있게 셔플링합니다.
3. **같은 카테고리에서 5개 선택한 경우**: 모두 동일한 $P_{category}$ 페널티를 받아 점수 격차가 상쇄됩니다. 결국 선택 순서대로 5일이 꽉 차게 되는데, 영적 피로를 막기 위해 **시스템이 강제로 3일 차에 타 카테고리의 '환기용 브릿지 주제'(예: 위로의 시편 등)를 1개 삽입**하여 숨 고르기를 유도합니다.
4. **위기 주제가 포함된 경우**: 초기 점수에 부여된 +1000점으로 인해 어떠한 페널티를 받아도 압도적 1위를 유지합니다. 즉각적인 영적 처방을 위해 무조건 1일 차(최우선)에 배치됩니다.

### 5. 최종 알고리즘 의사코드 (Pseudocode)

```python
# 상수 및 가중치 테이블 정의
WEIGHT_TABLE = { ... } # 위의 2번 표 데이터

def generate_qt_curriculum(maturity, duration, selected_topics):
    N = len(selected_topics)
    if N <= 1:
        return selected_topics

    # 1. 초기 점수 산출 (Initial Scoring)
    for i, topic in enumerate(selected_topics):
        base_score = WEIGHT_TABLE[maturity][topic.category]
        order_bonus = (N - i) * 2
        crisis_bonus = 1000 if topic.is_crisis else 0
        topic.initial_score = base_score + order_bonus + crisis_bonus

    curriculum = []
    remaining = selected_topics.copy()
    
    # 엣지 케이스 판별 (단일 카테고리 다수 선택 여부)
    unique_categories = set(t.category for t in remaining)
    is_monotone = (len(unique_categories) == 1 and N >= 4)
    
    prev_topic = None

    # 2. 동적 스케줄링 루프 (Dynamic Scheduling)
    while len(remaining) > 0:
        for topic in remaining:
            topic.dynamic_score = topic.initial_score
            
            if prev_topic:
                # 규칙 1: 카테고리 연속 방지
                if topic.category == prev_topic.category:
                    topic.dynamic_score -= 30
                    
                # 규칙 2: 무거운 주제 연속 방지 (분량 연동)
                if prev_topic.is_heavy and topic.is_heavy:
                    if duration == "짧음":
                        topic.dynamic_score -= 40
                    elif duration == "보통":
                        topic.dynamic_score -= 20
                    elif duration == "많음":
                        topic.dynamic_score -= 5
                        
        # 동적 점수가 가장 높은 주제를 추출하여 커리큘럼에 추가
        remaining.sort(key=lambda x: x.dynamic_score, reverse=True)
        best_topic = remaining.pop(0)
        curriculum.append(best_topic)
        
        prev_topic = best_topic

    # 단일 카테고리 쏠림 현상 시 숨고르기(Breather) 강제 삽입
    if is_monotone and len(curriculum) >= 3:
        breather_topic = get_system_breather_topic(maturity)
        curriculum.insert(2, breather_topic) # 3일 차에 환기용 주제 삽입

    return curriculum
```

**💡 [알고리즘 연산 증명] 예시 입력에 코드를 대입해 보면:**
1. **1일차 계산**: 불안(95점), 부부갈등(86점), 기도(79점)... → `[불안]` 선택 (Heavy)
2. **2일차 계산**: 직전이 `불안(Heavy)`이므로 `부부갈등(Heavy)`은 페널티(-20점)를 받아 66점으로 추락. 반면 `기도(Light)`는 페널티 없이 79점 유지 → `[기도]` 선택 (Light)
3. **3일차 계산**: 직전이 Light이므로 페널티 없음. 부부갈등 본래 점수 86점으로 복귀 → `[부부갈등]` 선택 (Heavy)

이처럼 동적 페널티 알고리즘을 통해 앞서 1번에서 극찬했던 **`[불안 → 기도 → 부부갈등 → 감사 → 직장생활]`**의 기독교 교육학적 황금 배치가 수학적으로 완벽하게 도출됩니다.

이전 분석에서 누락되었던 **사용자 라이프사이클(이탈 방지)**, **교회력 연동**, 그리고 **시스템 자동화(성숙도)**에 대한 핵심 엣지 케이스를 심층 분석해 드립니다. 

QA 엔지니어의 **'정교한 상태 관리(State Management) 및 방어 로직'**과 기독교 상담 전문가의 **'은혜 중심적 돌봄(Grace-based Care)'** 원칙을 통합하여 설계했습니다.

---

### 1. 이탈 방지 전략 (Churn Prevention)
기독교 앱에서 사용자가 이탈하는 가장 큰 원인은 **'밀린 숙제에 대한 정죄감(Guilt-tripping)'**입니다. 시스템은 사용자를 다그치는 대신, 언제든 돌아올 수 있는 '안전 기지' 역할을 해야 합니다.

*   **3일 연속 미완료 시 (단기 정체)**
    *   **시스템 동작:** 연속 출석(Streak) 깨짐 경고 등 압박감을 주는 UI를 숨깁니다. 기존 플랜의 진도율을 멈춰두고(밀림 방지), 기존 푸시 시간에 글쓰기가 필요 없는 '1절 말씀 팝업'을 부드러운 넛지(Nudge) 형태로 보냅니다.
    *   **UI 메시지:** "요즘 일상이 많이 분주하시죠? 주님은 묵묵히 기다리십니다. 오늘 하루, 딱 1분의 짧은 묵상으로 숨을 고라볼까요?"
*   **7일 미접속 시 (습관 단절 위기)**
    *   **시스템 동작:** 내부 상태를 `At-Risk`로 변경하고 기존 30일 플랜을 백그라운드에서 '일시 정지(Paused)' 처리합니다. 주말 등 여유로운 시간에 화면을 보지 않아도 되는 **'오디오(듣기 전용) 묵상'** 링크를 전송하여 진입 장벽을 극단적으로 낮춥니다.
    *   **UI 메시지:** "일주일 동안 참 수고 많으셨어요. 무거운 짐은 잠시 내려놓고, 눈을 감은 채 주님의 음성에 가만히 귀 기울여 보세요."
*   **30일 이상 장기 이탈 후 복귀 시 (재진입)**
    *   **시스템 동작:** 복귀 시 "Day 12" 같은 예전 진도를 들이밀거나 "35일 밀렸습니다"라는 표현을 절대 쓰지 않습니다. **'웰컴 백' 모달을 띄워 3일짜리 <영적 회복(Warm-up) 플랜>**을 최우선 제안합니다.
    *   **UI 메시지:** "다시 오실 줄 알았어요! 돌아오신 것을 진심으로 환영합니다. 예전 묵상을 무겁게 잇기보다, 가벼운 '회복 묵상'으로 다시 리듬을 찾아볼까요?"

### 2. 교회력/절기 연동 (Liturgical Calendar Integration)
절기 묵상은 보편 교회의 흐름과 개인을 연결하는 훌륭한 도구입니다. 하지만 **개인의 시급한 심리적/영적 위기를 덮어씌워선 안 됩니다.**

*   **사순절/성탄절 자동 추천 여부:** 적극 추천해야 합니다. 단, 기존 플랜을 강제 중단시키지 말고 화면 하단이나 상단 배너를 통한 **'투 트랙(병행)'** 옵션으로 제공해야 합니다.
*   **사용자 선택 주제와 절기 주제 충돌 시 (핵심 엣지 케이스):**
    *   **상담적 접근:** 사용자가 '우울/상실/트라우마' 극복 플랜을 진행 중인데, 사순절이라고 "자아를 십자가에 못 박고 철저히 회개하라"는 알림이 가면 심리적으로 무너질 수 있습니다.
    *   **시스템 동작:** 사용자의 현재 플랜 카테고리가 '위기/치유'일 경우, **무거운 절기 팝업 노출을 시스템에서 자동 억제(Mute)**하거나, 톤앤매너를 "우리의 아픔을 체휼하시는 위로의 십자가"로 동적 변경하여 보호해야 합니다.
*   **절기별 추천 주제 매핑 테이블:**

| 교회력 절기 | 기간 (대략) | 매핑 추천 주제 (커리큘럼 키워드) |
| :--- | :--- | :--- |
| **대림절** | 성탄 전 4주 | 기다림, 소망, 약속, 평안 |
| **성탄절** | 12월 25일 | 예수의 인성, 성육신, 구원, 기쁨 |
| **사순절** | 부활 전 40일 | 회개, 십자가 대속, 고난, 자기 부인 |
| **부활절** | 춘분 후 주일 | 부활, 승리, 새로운 생명, 죽음 극복 |
| **성령강림절** | 부활 후 50일 | 성령 충만, 사명, 교회의 하나됨 |
| **추수감사절** | 11월 셋째 주 | 감사, 공급하심, 은혜 계수하기 |

### 3. 성숙도 자동 상승 (Maturity Auto-progression)
입문자가 30일 QT를 3번 완료했다고 영적 소화력이 반드시 '초급'이 되는 것은 아닙니다. 강제 상승 시, 갑자기 어려워진 질문에 당황하여 이탈률(Churn)이 급증할 수 있습니다.

*   **해결책: "데이터 기반 조건부 넛지(Nudge) + 수동 수락(Opt-in)"**
    *   시스템이 강제로 올리지 않고, 성숙의 징후가 보일 때 축하 모달을 띄워 **사용자가 직접 단계를 올리도록 동의**를 구합니다.
*   **성장 트리거(감지 기준) - 아래 3가지 동시 충족 시:**
    1.  **완료 성실도:** 30일 플랜을 현재 단계에서 2회 이상 연속 완주했을 때.
    2.  **작성 빈도:** 최근 30일간 SOAP 작성률이 70% 이상일 때 (빈칸 스킵이 적음).
    3.  **SOAP 깊이(가장 중요):** 단순 "아멘", "좋았다" 같은 단답형을 제외하고, 주관식 적용(A) 및 기도(P) 란의 평균 글자 수가 **50자 이상 지속**될 때.

### 5. 나눔 탭과 QT 연동: 안전하고 은혜로운 공동체 구축

익명 기반의 영적 나눔터는 큰 위로가 되기도 하지만, 이단 침투, 타인 비방, 심리적 전염(극단적 우울/자살 모의) 등의 치명적 리스크(Risk: 상)를 내포하고 있습니다. 철저한 예외 처리가 필요합니다.

**1) QT 완료 후 자동 공유 제안 로직**
*   **상담적 분석:** 모든 묵상을 기계적으로 공유 제안하면 안 됩니다. 내밀한 죄의 고백이나 깊은 상처(트라우마, 학대 등)를 묵상한 직후에 "이 은혜를 나누시겠어요?"라고 묻는 것은 프라이버시 보호에 취약하며 충동적인 감정 배설을 유도할 수 있습니다.
*   **시스템 동작 (조건부 제안):** 
    *   **공유 권장 주제:** '감사, 일상, 찬양' 등 보편적 주제 완료 시에만 부드러운 팝업으로 나눔을 제안합니다.
    *   **공유 차단(Mute) 주제:** 위기/심화 주제 완료 후에는 **공유 제안 팝업 자체를 시스템에서 강제 숨김(Mute)** 처리합니다.
    *   **부분 공개 디폴트:** 공유 시 본문의 성경(S)과 관찰(O)은 공개되게 하되, 가장 사적인 적용(A)과 기도(P) 영역은 디폴트로 **'비공개(토글 OFF)'** 상태로 두어 사용자가 명시적으로 선택(Opt-in)할 때만 퍼블릭에 노출되도록 방어합니다.

**2) 부적절 내용 필터링 및 신고 누적 처리 프로세스 (Escalation Matrix)**
*   **1차 (사전 필터링):** 이단 키워드(신천지, JMS 등), 심한 욕설, 상업적 링크는 작성 완료(Submit) 클릭 시 클라이언트 단에서 즉시 차단합니다.
*   **2차 (신고 누적 Auto-Blind):** 익명이므로 서로 다른 유저 **3명의 신고가 누적되면 즉시 해당 글을 자동 숨김(Soft-delete)** 처리하고 관리자 리뷰 대기열로 이관하여 커뮤니티 오염을 막습니다.
*   **3차 (긴급 구조 프로토콜):** 신고 사유가 **'자살/자해 암시'**인 경우, 단 1회 신고만으로도 즉시 블라인드 처리하며, 작성자의 앱 화면에 [109 생명의 전화] 등 긴급 위기 상담 팝업을 강제 노출합니다. (정죄가 아닌 구조 목적)
*   **4단계 (악성 유저 섀도우 밴):** 관리자 확인 결과 이단 포교나 악의적 비방이 맞다면, 해당 기기/계정에 **'섀도우 밴(Shadowban)'**을 적용합니다. 본인은 글이 정상 등록된 것처럼 보이나 타인에게는 절대 노출되지 않습니다. (단, 개인 QT 기능은 차단하지 않아 긍휼의 통로는 열어둡니다.)

### 6. 알림/리마인더 전략: 율법주의 없는 동기부여

신앙 앱의 알림이 **"너 또 말씀 안 읽었네? 연속 출석 깨진다!"**라는 감시자(Taskmaster)처럼 느껴지는 순간, 사용자는 정죄감을 이기지 못하고 앱을 삭제합니다. 알림은 항상 **"주님이 널 기다리셔"**라는 동역자의 초대여야 합니다.

**1) 푸시 발송 타이밍 (사용자 주도권)**
*   **해결책:** 일괄 아침 7시 푸시는 교대 근무자나 야행성 유저에게 공해입니다. 온보딩 시 "하루 중 주님과 가장 편안하게 만나는 시간은 언제인가요?"라고 질문하여 **직접 리마인더 시간을 설정**하게 합니다. 발송 시에는 정각 대신 ±5분 내외의 랜덤 오프셋을 두어 인격적인 넛지(Nudge) 느낌을 줍니다.

**2) 미완료 기간에 따른 메시지 톤앤매너**
*   ❌ **최악의 톤 (압박/정죄):** "3일째 쉬고 있어요", "오늘의 묵상을 완료하세요." (영적 패배감 유발)
*   🔺 **아쉬운 톤 (의무감):** "괜찮아요, 내일 이어서 해요." (여전히 밀린 '숙제'라는 뉘앙스)
*   ⭕ **최선의 톤 (은혜/초청 - Feeding over Doing):** 행위를 촉구하지 말고, 앱에 안 들어와도 은혜를 받게끔 '말씀 자체'를 배달하여 진입 장벽을 낮춥니다.
    *   **당일 미완료 (설정 시간 +2시간):** "오늘 하루 많이 분주하셨죠? 이동하는 중 이 말씀 한 구절로 마음을 토닥여볼까요? [오늘의 성경 1구절]"
    *   **3일 미접속:** "숨 가쁜 일상, 잠시 멈춤표가 필요할 때 언제든 열어주세요. 주님은 늘 같은 자리에서 기다리십니다."
    *   **7일 미접속:** 글을 읽을 에너지조차 없는 상태입니다. "많이 지치셨나요? 글을 읽지 않아도 괜찮아요. 눈을 감고 오늘의 말씀을 편안하게 들어보시겠어요? [오디오 묵상 링크]"
